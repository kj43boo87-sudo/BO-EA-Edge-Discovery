# JST検証ログ

リポジトリのルートから、使用する仮想環境のPythonで実行する。

```bash
.venv/bin/python scripts/run_logged.py --category UTL --case-id unknown --input data/sample/bars.csv -- .venv/bin/python -m pytest
```

`--` より後ろが実行するコマンド。シェル展開は行わない。コマンドの作業ディレクトリは常にリポジトリルート。
入力ファイルは `--input` で複数指定でき、SHA-256を記録する。入力の指定は任意だが、データを用いる検証では全入力を明示する。

reports/run-<JST日時>-<一意ID>.json に、開始・終了日時（+09:00）、SYS/UTL/DEV/BO/FX/STK/RES/MISC区分、案件ID、実行コマンド、Python・依存バージョン、Gitコミットと変更状態、入力ハッシュ、標準出力・標準エラー、終了コードを記録する。案件IDは既定でunknown。
スキーマv2では、`wrapper_environment` はログを取るPythonとその依存だけを表す。`command_environment.status` は `unverified` で、任意の対象コマンドのPython/依存を推測しない。別Python・別venv・シェル経由の対象も同様。対象側で `sys.executable`、`sys.version`、依存版などを出力して確認しない限り、対象環境の再現情報が取得済みとは扱わない。

正式ログはGitリポジトリのクリーンなコミット限定。追跡済み変更・ステージ済み変更・未追跡ファイルがある場合は実行を拒否し、状態と理由を残す。正式実行前に作業ブランチへコミットする（mainへのマージは不要）。ignoredファイル・リポジトリ外の実行コード・外部サービスの内容はコミットでは保全されないので、そうしたコードを正式検証に使わず、入力は全て明示しハッシュを取得する。実行中に他の担当がコードを変更しないこと。データ/外部資源が実行中に変化しないことも利用者が確認する。

終了コードは次のように分離する。

- `raw_returncode`: 対象プロセスの生のreturncode。未起動ならnull。
- `termination_signal`: POSIXシグナル終了なら正のシグナル番号、それ以外はnull。
- `wrapper_exit_code`: 通常終了は対象のコード、シグナルNは128+N。例: SIGTERMはraw=-15、signal=15、wrapper=143。
- `exit_code`: v1互換の名前としてwrapper_exit_codeと同値。シグナル時の意味はv1から変更。
- Git不備・入力読込/ハッシュ失敗・依存取得失敗は準備失敗の2。コマンド起動不能は127。

対象終了コード0のみpassed、それ以外はfailed。開始ログを入力確認より前に作るため、存在しない入力・ディレクトリ指定・読込権限エラーも記録する。引数の構文エラーや保存先自体へ書けない場合はログを作れない。ラッパー自身の強制終了時に残るrunningは成功ではない。ラッパー自身へのシグナル転送・実行中のタイムアウト管理は今回の修正範囲外。

ログはGit対象外。コマンド引数・標準出力・標準エラーに認証情報を含むコマンドは記録しない。環境変数や認証ファイルは収集しない。
出力はメモリ上で収集するため、大容量Tickデータそのものを標準出力に流さず、集計結果やファイルパスを出力する。

結果の解釈は次のひな形で別途記録する。終了コード0は当該コマンドの成功だけを示し、戦略の有効性を保証しない。

```text
日時: YYYY-MM-DDTHH:MM:SS+09:00
区分: UTL / 案件ID: unknown
実行ログ: reports/run-....json
目的・比較対象:
実測事実:
仮説:
未検証事項:
除外データと理由:
評価方法・時系列分割（市場検証時）:
試行数・OOSの取扱い（市場検証時）:
変更内容・未解決事項:
```

ログの永続保存先は未確定。[退避・復元手順](evidence-retention.md) を参照し、クラウド環境を破棄する前に読み戻しまで確認する。
