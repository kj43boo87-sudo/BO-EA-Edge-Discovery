# 実データの受入ルール

この手順は受入確認のためのものです。ひな形の作成だけでは検証可能なデータとは扱いません。

1. 原本を data/raw/ に配置する。上書きせず、取得単位で別ファイルにする。認証情報は含めない。
2. docs/templates/data-metadata.json を data/raw/<データ名>.metadata.json にコピーする。実データとメタデータはGit対象外。
3. 生成元の提供者・参照資料・取得日時（オフセット付きISO 8601）・利用条件・銘柄・時間足を記録する。生成元不明なら excluded のままとし、reason に理由を記録する。
4. ファイルのSHA-256を `sha256sum data/raw/<ファイル名>` で取得して記録する。原本の識別と改変検出に使い、生成元の正当性の証明とは扱わない。
5. 時刻基準、タイムゾーン、夏時間、OpenTime/CloseTimeの定義、配信遅延を提供元の根拠とともに確認する。推測による固定時差補正は禁止。不明な仕様は未検証と明記して対象外にする。
6. 欠損・重複時刻・時刻順序・開始終了時刻の整合性を確認し、quality_checks に実測結果と確認方法を記録する。足の欠落を未来データで補完しない。
7. 確認者・JST確認日時・判断根拠を記入し、確認できた場合のみ status を accepted に変更する。未確認は excluded、除外理由を残す。これは手動受入手順であり、自動認証機能ではない。

加工データは data/processed/ に別ファイルとして保存し、元ファイルのハッシュ、実行コードのGitコミット、実行コマンド、加工履歴を記録する。
BO/FX/STKの仕様と評価指標を分ける。案件ID不明はunknown。source.referenceやログにURLの認証トークンなどを保存しない。
人工サンプルは data_kind を synthetic として生成方法を明示し、実市場データと混同しない。
